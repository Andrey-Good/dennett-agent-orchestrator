# Dennett

**Dennett — постоянно действующая агентная операционная среда.** Человек общается с агентами; система хранит поручения и память, организует исполнение и ожидание, управляет полномочиями и ресурсами и допускает развитие моделей и инструментов.

> **2026-09-26: бизнес-логика и согласованная архитектурная редакция 2.0 зафиксированы в `restart/spec-v2`.** Следующий отдельный этап — процесс разработки агентами и приёмки. Этот репозиторий не объявляется готовой реализацией новой архитектуры; приложение и main в документационном цикле не переписываются.

## Устройство

UI и постоянное исполнение разделены. Полноценный агент Dennett сохраняет конфигурацию, контекст и поручения поверх готового Codex/Claude/другого harness. CLI/MCP и интерфейс используют одни функции; native tools исполняет их движок.

**Память — самостоятельный процесс `dennett-memoryd`**, пригодный для внешнего агента без Head и UI. PostgreSQL — единственная canonical server database; SQLite клиента хранит лишь offline staging/cache. Полный резервный ПК содержит серверный комплект, SQL-реплику и нужные файлы/ключи. Один Head имеет действующую власть; потеря сети не создаёт второго автоматически.

Смысловые связи агентов описываются текстом. Код обеспечивает сохранность, права, остановку и доставку, а не обязательную мыслительную последовательность. Автоулучшение реально сравнивается с прежним вариантом и проверяется на регрессии, перенос и расходы.

Графика свободно сочетает текст, обычные файлы, custom HTML и готовые интерактивные средства. MCP Apps/A2UI/AG-UI — подходящие адаптеры, не обязательная цепочка каждого ответа.

## Код, история и проверка

Исходная реализация, тесты и история сохранены. Прежние тома доступны в [точном архиве](docs/archive/architecture-2026-07-13/README.md). Решение о сохранении/замене частей кода относится к следующему процессу разработки, а не к факту наличия каталога.

Документальная согласованность не доказывает работоспособность. Native integrations, replica/fencing, restore, performance и полный CI должны быть проверены в реализации. Ограничение полного checkout и оставшийся долг generated manifests/checksums явно указаны в [статусе](docs/restart/README.md). Ветка не объявляется готовой к main/release на основании текста.

## Безопасность и лицензия

Не публикуйте секреты и приватные рабочие данные. Для уязвимостей действует [SECURITY.md](SECURITY.md). Архитектурная правка не расширяет выданные агентам права и не разрешает обход условий поставщиков.

Лицензия ещё не выбрана; этим изменением она не устанавливается. Описание прежних milestones и команды их разработки доступны в истории Git, не как подтверждение текущей реализации.
