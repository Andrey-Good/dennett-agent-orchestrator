# Приёмка первого Claude runtime

Версия 1.0 · 2026-09-27. Применяется по [контракту M](../specifications/contracts/M_Runtime_Rollout_Contract.md), [тому82 §5](../architecture/82_Dennett_Agent_Voice_Capability_and_Integration_Architecture.md#5-claude-code-и-claude-agent-sdk) и [общей стратегии тестов](TEST_CATALOGUE_AND_QUALITY_GATES.md). Это задания будущим тестам, **не отчёт о пройденных canary**. D0–D9 и остановки H0–H9 сохраняются.

Для каждого заявляемого SDK/CLI/auth mode фиксируются версии, реально включённые настройки, изолированный профиль, test/build commit и результаты. Успех SDK не доказывает полноту CLI, вход через API не доказывает подписочный путь. Не обязательно реализовать оба способа сразу; H1 требует один разрешённый полноценный Claude-путь. Дополнительный маршрут считается поддержанным только после его проверок. Недоступные аккаунты не заменяются чужими токенами или ложным успехом.

## D0/D1: первый рабочий путь

**C01. Подключение и состав поставки.** На чистом профиле без Codex, ChatGPT-входа и OpenAI-зависимостей проходит первое реальное Claude-поручение. Неверный путь к бинарнику, неподдержанная версия и отсутствие авторизации дают отдельную диагностируемую ошибку. Проверить фактический auth/billing mode; отказ входа не переключает на платный API или другой provider. Fake допускается для воспроизведения ошибки, но не для зачёта живого подключения.

**C02. Контекст и настройки.** Для coding-сессии проверяется выбранный preset/append, для не-кодирующего агента — его явный профиль. Разрешённая проектная инструкция действительно загружается; личная инструкция, auto-memory, connector и исполнимый hook чужого тестового профиля не подмешиваются. Отдельно проверяются настройки, не управляемые одним `settingSources`. При применении `--bare` проверять потерю автозагрузки и несовместимость с подписочным входом, а не считать это безусловным default. Native policy не обходится ради изоляции.

**C03. Memory Fabric, не просто history Claude.** Внешний клиент записывает факт через отдельный memoryd при выключенном Head. После подключения Head Claude получает этот факт вызовом нашего инструмента, использует для фактического результата, записывает разрешённое изменение. Другой scope получает отказ. Перезапуск сохраняет факт и его источник. Native transcript/auto-memory не может быть единственной копией. MCP и CLI, когда оба заявлены, вызывают одну доменную операцию.

**C04. Изолированные сессии.** Создать два разговора в одной папке с разными фактами; после перезапуска возобновить по точным ID и не смешать контекст. Fork не меняет оригинал и не выдаёт дополнительные права. Проверить отсутствующий/повреждённый transcript и несовпадающую рабочую область: явный rehydrate/ошибка, не ложный resume. Изменение модели не создаёт нового Dennett Agent.

**C05. Реальные полномочия.** Проверить разрешённое и запрещённое действие, отзыв между подготовкой и запуском, tool auto-allow до `canUseTool`, проверку `PreToolUse`, отказ policy-сервиса и попытку аналогичного доступа через Bash/сеть. Hooks и callbacks не заменяют ограничения среды. Сведения в CLI-аргументе не выдают credential; native tool и наш broker не выполняют действие дважды. Проверка запрета без работающего разрешённого случая недостаточна.

**C06. Поток ввода, вопросы и прерывание.** Во время работающей сессии подать уточнение, получить и разрешить `AskUserQuestion`, отдельно ответить на approval, затем проверить отказ и Stop. Ответ прикрепляется к правильной попытке и параметрам; позднее разрешение после Stop не исполняется. Не считать output streaming доказательством поддержки input streaming. Неподдержанный CLI-mode не принимает всё автоматически; выбранный полноценный путь обязан пройти тест.

**C09. Ошибки и корректный итог.** Воспроизвести ошибка-результат, разрыв потока, nonzero exit, зависший запрос ввода, превышение разрешённого бюджета, истёкший вход и падение host. Финальный текст не превращается в успешный результат при ошибке или незавершённом действии. Есть диагностика без credentials и восстанавливаемое явное состояние. Известные usage-события не суммируются повторно; отсутствие цены не считается нулевой ценой. Лимит поставщика и лимит Dennett различаются.

## Следующие этапы

**C07. Помощники — D2/D3.** Нативный помощник выполняет самостоятельную часть без нашей JSON-анкеты. Проверяются его фактические инструменты, memory scope, бюджет и применимость hooks; ordinary subagent не считается fork полного контекста. Недоступный ему вопрос пользователю возвращается через родителя. Отдельные агенты Dennett могут общаться текстом без обязательной CLI-only agent team. Отмена и late result не ломают другую нужную работу.

**C08. Skills, plugins и MCP — D3.** Подключить разрешённый навык, плагин и сервер, проверить фактическую загрузку/доступность, отключение и изменение версии. Пользовательские файлы не переписываются молча. Конфигурация, отключающая инструмент навыков, должна обнаруживаться; поддержка интерфейса не выводится из одного имени пакета. Подключения из личного аккаунта не получают доступ ко всем проектам автоматически.

**C10. Долгая работа, остановка и резерв — D2/D5.** Закрытие UI не завершает нужный runtime. Закрытие процесса CLI и его фоновые задачи не имитируют долговечный таймер Head. При interrupt/аварийном kill исход уже начатого действия сохраняется, перед resume он проверяется. На резервном узле проверяются файлы сессии/проекта и доступная авторизация, а не только ID. Недоступный credential не копируется из чужого профиля и не создаётся новый оплачиваемый маршрут без разрешения.

**C11. Материалы и интерфейс — D4/D6.** Через выбранный Claude-путь передать изображение/файл и контекст выделения по L, получить обычный артефакт и отображаемый вопрос. Не предполагать, что SDK является готовым ASR/TTS/realtime-audio сервисом. Перезапуск панели не повторяет инструмент; метки в UI различают SDK-backed агента и действительно запущенный официальный CLI.

**C12. Обновление и границы выпуска — непрерывно, итог D9.** Повторить применимые предыдущие сценарии после смены SDK/runtime, auth mode или настроек. Версия из lockfile и фактически запускаемый бинарник должны совпадать с отчётом. Все C-сценарии текущих возможностей имеют доказательства на итоговой сборке, не только старом коммите. Codex остаётся явно planned R-CODEX и не маскируется под skipped успешно проверенный provider. После отдельной активации R-CODEX нужны собственные живые canary; общий fake-port этого не заменяет.

## Правило зачёта

На H1 обязательны C01–C06 и C09 для выбранного первого маршрута; C07/C08 — к H3, C10 — к H5, C11 — к H6, весь применимый регрессионный набор — к H9. Ранние части выполняются по мере появления функции, не откладываются до конца этапа. Каждая намеренная ошибка создаётся только на одноразовых проектах, профилях и тестовых получателях; проверяется, что она случилась именно в требуемой точке. Тест не может объявить функциональность поддержанной на основании красивого ответа модели.
