# Покрытие требований новой реализации

Инициализировано 2026-09-27. **Все записи ниже — назначение будущей работы, не пройденные тесты.** Для новой реализации исходный статус каждой области и V/L-сценария — «не реализовано, не проверено». Статус этапов хранится только в [STATUS](../implementation/STATUS.md).

## 1. Как дополнять карту

В D0 сверить каждое нормативное семейство и раздел документов 00–70, F01–F10, E01–E10, A–L/90 с этапом ниже. Конкретные обязательные пользовательские сценарии детализировать перед соответствующим этапом. У каждой записи должны появиться ссылка на требование, владелец этапа, критерий, реальный тест/ручная проверка, commit/build и результат. Формат может оставаться Markdown; обязательный JSON-реестр и собственный task engine не нужны.

Отсутствующий тест остаётся отсутствующим, а не «не применимо» по желанию агента. Действительно неприменимый тест имеет причину и ссылку на границу требования. Каждый работающий обязательный путь входит в регрессии последующих этапов. Один сквозной тест может покрывать несколько связанных требований, но не заменяет специфические негативные и граничные случаи.

Примеры/исследовательские альтернативы не автоматически становятся обязательными backend-реализациями. И наоборот, требуемый результат нельзя объявить необязательным только потому, что его трудно сделать. Сокращение согласованного продукта требует отдельного решения владельца и не выдаётся за завершение исходной программы.

## 2. Семейства продукта → этапы

**P01. Установка, запуск и остановка.** D0/D1/D9. Чистое окружение, независимая жизнь UI/Node/Head/memoryd, безопасный профиль, явная диагностика отсутствующих возможностей. Источники: 50/60/61, архитектура 80/83.

**P02. Агенты, разговор и модели.** D1/D2/D3. Единая сущность, прямой разговор, сохранение истории, native continuation/steer, смена настройки без новой личности, нужные помощники и текстовая кооперация. Источники: F01–F05/F10, 20/41/82.

**P03. Поручения, ожидания, события.** D2/D5. Durable tasks/runs, расписания, сигналы, пропущенное/позднее, отмена, бюджеты, Inbox/Radar. Источники: 20/50, I, F07.

**P04. Самостоятельная Memory Fabric.** D1/D3. Запись/чтение без Head, provenance, исходники и рабочие документы, текущая версия и история, ограничения области. Источники: 10/80/81.

**P05. Обработка и поиск памяти.** D3. Дедупликация, отбор, сжатие/обобщение, retrieval и актуальность, мультимодальные evidence, ссылки на источники, влияние инструкций, коррекция/конфликт/удаление. Индексы восстановимы и не единственный источник данных. Источник: 10; выбор необязательных усилений — по проверке, не по количеству компонентов.

**P06. Проекты и рабочие материалы.** D1/D2/D3/D9. Создание/открытие/архив/удаление/перепривязка, файлы и Git/workspaces, пользовательские правки, перенос и продолжение. Источники: C, 20/50/60; отдельная новая функция «восстановить старый проект» не требуется.

**P07. Артефакты.** D1/D4/D7/D9. Версии, редактируемые исходники, representations, просмотр/экспорт, публикация и отзыв, повторное открытие без повторного эффекта. Источники: D/J/L.

**P08. Права, доверие, аккаунты и секреты.** С D1 на всех этапах, полный цикл D5/D7/D9. Allow/deny/expiry/revoke, границы исполнения native tools и наших tools, exact approval, recovery/step-up, недоверенные данные и минимизация раскрытия. Источники: 30, F, 82/83. ## 3. V01–V29 — назначение существующих архитектурных сценариев

Ни один V-сценарий пока не выполнен. После реализации к каждой записи добавляется ссылка на тест, build и фактический результат, а не новая копия его нормативного текста.

- V01/V02 — standalone memoryd и Head при отказе памяти: D1, регрессии D3+.
- V03 — закрытый UI не завершает систему: D1, device-повтор D5.
- V04–V06 — агент использует память, один native executor, CLI/MCP-права: D1/D3, real canary при обновлении адаптера.
- V07 — уточнение/отмена общей работы без графа потребителей: D2, agent eval и наблюдаемый эффект.
- V08–V14 — read-only reserve, lag/files, transfer, partition, возврат primary, sync timeout и WAL pressure: D5, release-regression D9.
- V15–V18 — committed cursor, per-key order, crash после доставки, snapshot/subscription: D2 на настоящем PostgreSQL; D5 с сетью.
- V19 — evidence link с optional ordinal и несколькими anchors: D1/D3.
- V20–V22 — край retention, незавершённый RecoveryCut, restore после revoke/forgetting: D5/D9; базовый restore начинается D1.
- V23–V26 — файлы/HTML, выделение, совместное редактирование, несколько UI и устройств: D4; D5/D6 расширяют.
- V27 — прерывание речи и ambient privacy: D6.
- V28 — плохое самоулучшение не принимается: D8.
- V29 — смена provider session/terms/version без ложного resume: D1/D3, перед release D9.

L.9.1–L.9.10 полностью назначены D4; multi-device/voice части допроверяются D5/D6. Их статус не наследуется из одобрения самого контракта L.

## 4. Финальный аудит отсутствующих функций

Перед H9 пройти каждый действующий документ 00–70 и дополнения, а не только названия P01–P23. У каждого обязательного поведения должна быть запись реализации/проверки. Отсутствующее требование добавляется в карту с этапом и тестом, не заменяется общим «покрыто P13». Просмотр скриншота не засчитывается как проверка серверного эффекта.

Финальная запись содержит проверенный установочный пакет, целевые ОС/версии, миграцию/restore, пройденные critical V/L, незапущенные/падающие проверки и принятые ограничения. Демо-ядро можно использовать как пилот раньше, но это не закрывает H9.
