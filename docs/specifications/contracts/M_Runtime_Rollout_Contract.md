# M. Первый runtime и отложенная поддержка провайдеров

Версия 1.0 · 2026-09-27. Согласованное решение владельца. Primary owner: Capability / Agentic Control (41/20). Применяется вместе с F01–F10 и [реестром приоритетов](../../restart/README.md).

## M.1. Приоритет продукта

**Первый реальный агентный движок Dennett — Claude Code.** Используется готовый цикл Anthropic через официальный Agent SDK или подходящий документированный CLI-режим; прямой вызов модели без этого цикла не считается выполнением требования. Конкретная модель, effort и модель, которой разработчик пишет код Dennett, этим решением не закрепляются.

D0 проверяет совместимость Claude-пути, D1 создаёт первый рабочий разговор с реальной памятью и инструментами на Claude. D2/D3 развивают его нативные возможности. При отсутствии доступа или нужной функции агент сообщает блокер; он не переключает первую реализацию на Codex, тестовую модель или платный способ без согласования.

## M.2. Codex сохраняется, но не входит в текущий выпуск

Codex остаётся описанным будущим адаптером. Его реализация, зависимости, установка, ChatGPT-вход и live-canary **не требуются на D0–D9 и не блокируют H0–H9**. Нет фонового автоматического fallback на Codex. В каталоге его можно показывать только как «запланировано», не «подключено» или «поддерживается».

После текущего цикла отдельный пункт **R-CODEX** может быть активирован явным решением владельца. Тогда требуются актуальные протоколы, условия входа, реальная интеграция и собственные canary. Сохранённый §4 тома82 — проект будущего подключения, не задача начать его немедленно. Остальные обязательные функции Dennett не отменены этим исключением.

## M.3. Поведение и способы входа

Агент Dennett сохраняет идентичность, память, поручения и права поверх движка. Нативные инструменты выполняет Claude; наши операции выполняют Head/Node/memoryd через общие CLI/MCP-фасады. Память доступна по ходу работы, а не только как журнал после ответа. Обычный текст, файлы, собственная графика и контекст выбора сохраняются по L.

Для встроенного продукта Agent SDK — рекомендуемый программный путь. Официальный CLI сохраняется для сценариев, которые он действительно поддерживает, включая штатный пользовательский вход в неизменённый бинарник. Разные способы авторизации и оплаты показываются явно; нельзя обещать универсальную подписочную авторизацию SDK или молча включать расход API. Точные границы по официальной документации описаны в [томе82 §5](../../architecture/82_Dennett_Agent_Voice_Capability_and_Integration_Architecture.md#5-claude-code-и-claude-agent-sdk).

SDK-backed агент не выдаётся за официальный продукт Anthropic: используется корректное обозначение «Claude Agent»/«Claude» либо имя агента Dennett. Если действительно запущен официальный Claude Code, это можно сообщить как факт, без присвоения бренда. Цель системы остаётся шире программирования: роли и инструкции выбираются по поручению, а не навсегда по терминальному coding-профилю.

## M.4. Область приоритета и приёмка

M уточняет порядок и заявляемую поддержку в бизнес-документах 00/01/20/41/60/61/70, K/90, архитектуре и плане. Перечисление Codex рядом с Claude, пример Codex-сессии или термин «first-class adapter» в прежнем тексте означает сохранённую целевую возможность, **не обязательность её реализации сейчас**. Поведение общего проектного чата остаётся прежним. Исторические материалы не переписываются под сегодняшнего провайдера.

Текущий экземпляр архитектурного V04 проверяется на Claude; будущий вариант на Codex относится к R-CODEX. Общие проверки runtime действуют для реально заявленных поддержанных путей. Проверки, отложенные вместе с Codex, не считаются пройденными. Обязательные сценарии Claude собраны в [CLAUDE_RUNTIME_ACCEPTANCE.md](../../testing/CLAUDE_RUNTIME_ACCEPTANCE.md); обоснования и ограничения — [CR01–CR14](../../research/2026-09-27_claude_runtime_evidence.md).
