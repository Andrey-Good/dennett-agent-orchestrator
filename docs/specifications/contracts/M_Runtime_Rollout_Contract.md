# M. Первый runtime и отложенная поддержка провайдеров

Версия 2.0 · 2026-11-23. Согласованное решение владельца (заменяет редакцию 1.0 от 2026-09-27 о Claude-first). Primary owner: Capability / Agentic Control (41/20). Применяется вместе с F01–F10 и [реестром приоритетов](../../restart/README.md).

## M.1. Приоритет продукта

**Первый реальный агентный движок Dennett — родной движок Google Antigravity (`agy acp`).** Используется готовый агентный цикл Google Antigravity через документированный двусторонний протокол **Agent Client Protocol (ACP v1, JSON-RPC over stdio)**; прямой вызов модели без этого агентного цикла не считается выполнением требования. Конкретная модель, thinking level и модель, которой разработчик пишет код Dennett, этим решением не закрепляются.

В первом runtime с первого дня разделяются **два явных профиля авторизации**:

- **Интерактивный профиль (`oauth-personal`, подписка Google AI Ultra):** основной маршрут для живого пользовательского чата и интерактивной работы через штатный локальный вход Antigravity CLI (`agy` / `agy acp --login`, системный keyring).
- **Автономный/фоновый профиль (`gemini-api-key`, переменная `GEMINI_API_KEY`):** отдельный изолированный профиль для будущих безлюдных фоновых задач, расписаний и headless-автоматизации, где интерактивный браузерный вход недоступен или неуместен.

D0 проверяет совместимость `agy acp` (handshake, версии, передачу MCP-инструмента памяти, permission callback, отмену и изоляцию профилей), D1 создаёт первый рабочий разговор с реальной памятью `memoryd` и инструментами на `agy acp`. D2/D3 развивают его нативные возможности и фоновый профиль. При отсутствии доступа или нужной функции агент сообщает блокер; он **не переключает** интерактивный профиль подписки молча на оплачиваемый API-ключ, на Claude Code, на Codex или на тестовую заглушку без явного согласования владельца.

## M.2. Claude Code и Codex сохраняются как отложенные адаптеры

**Claude Code (`R-CLAUDE`)** и **Codex (`R-CODEX`)** остаются описанными будущими адаптерами. Их реализация, зависимости, установка, пользовательский вход и live-canary **не требуются на D0–D9 и не блокируют H0–H9**. Нет фонового автоматического fallback на Claude Code или Codex. В каталоге возможностей их можно показывать только как «запланировано», не «подключено» или «поддерживается».

После текущего цикла отдельные пункты **R-CLAUDE** и **R-CODEX** могут быть активированы явным решением владельца. Тогда требуются актуальные протоколы, условия входа, реальная интеграция и собственные canary. Сохранённые в [томе 82](../../architecture/82_Dennett_Agent_Voice_Capability_and_Integration_Architecture.md) §4 (Codex App Server) и §5 (Claude Code / Claude Agent SDK) остаются проектами будущего подключения, не задачей начать их немедленно. Остальные обязательные функции Dennett не отменены этим исключением.

## M.3. Поведение, границы и способы входа

Агент Dennett сохраняет идентичность, память, поручения и права поверх движка. Нативные инструменты (`read_file`, `edit_file`, `run_command` и т.д.) исполняет `agy acp`; операции Dennett выполняют Head/Node/`memoryd` через общие MCP/CLI-фасады без повторного исполнения нативного инструмента нашим broker. Память доступна по ходу работы через подключённый MCP-сервер или CLI `memoryd`, а не только как журнал после ответа. Обычный текст, файлы, собственная графика и контекст выбора сохраняются по контракту L.

Техническая граница адаптера `agy acp`:

- Транспорт: локальный subprocess `agy acp` по JSON-RPC 2.0 over `stdin`/`stdout` (ACP v1), отдельные диагностические логи (`--log-file`), явная привязка к версии бинарника `agy` и его `agentCapabilities`.
- Изоляция профиля: для тестовых, фоновых и изолированных профилей применяются `--app-data-dir`, `--gemini-dir`, `--include-default-customizations=false` (где требуется), `--process-per-session` и `--sandbox`. Флаг `--dangerously-skip-permissions` запрещён в обычном режиме и допустим только в явно обозначенной одноразовой песочнице.
- Управление ходом: нативные ACP операции `session/new`, `session/load`/`resume`/`list`/`close`, `session/prompt`, `session/cancel`, steering, `session/request_permission` и elicitation/вопросы; `systemPrompt.append` и проектные инструкции передаются явно без смешивания с чужим профилем.
- Авторизация и прозрачность: фактический профиль (`oauth-personal` с отображением tier подписки либо `gemini-api-key`) и его биллинговая граница всегда видны пользователю; `GEMINI_API_KEY` и токены OAuth никогда не сохраняются в открытых проектных конфигах, не попадают в логи и не копируются в чужой профиль при failover.

Агент Dennett, работающий поверх `agy acp`, обозначается в интерфейсе своим именем Dennett и честной технической ссылкой на движок `Antigravity ACP` и выбранный профиль входа, без присвоения чужого бренда и без привязки всех агентов исключительно к coding-роли.

## M.4. Область приоритета и приёмка

Редакция 2.0 контракта M уточняет порядок и заявляемую поддержку runtime поверх прежнего текста бизнес-документов 00/01/20/41/60/61/70, K/90, архитектуры (включая том 82 §4–§5) и плана D0–D9. Перечисление Claude Code или Codex как первого/основного движка в документах от 2026-09-26..27 означает сохранённую целевую мультипровайдерную способность, **не обязательность их реализации сейчас**. Поведение общего проектного чата, независимость `memoryd`, PostgreSQL и все остальные требования D0–D9 остаются прежними. Исторические архивы не переписываются задним числом.

Текущий экземпляр архитектурного V04 проверяется на **Google Antigravity (`agy acp`)**; будущие варианты на Claude Code и Codex относятся к `R-CLAUDE` и `R-CODEX`. Обязательные приёмочные сценарии первого движка собраны в [ANTIGRAVITY_RUNTIME_ACCEPTANCE.md](../../testing/ANTIGRAVITY_RUNTIME_ACCEPTANCE.md) (`A01–A12`). Прежний чеклист [CLAUDE_RUNTIME_ACCEPTANCE.md](../../testing/CLAUDE_RUNTIME_ACCEPTANCE.md) (`C01–C12`) сохранён для будущего этапа `R-CLAUDE`. Проверки, отложенные вместе с Claude Code и Codex, не считаются пройденными.
