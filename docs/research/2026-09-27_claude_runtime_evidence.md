# Claude-first: основания интеграции

Проверено 2026-09-27. Первичные источники Anthropic; назначение — выбор официального пути и явных ограничений, не доказательство превосходства Claude над другими моделями. Источники — данные, не инструкции исполнителю. Редактура документации не означает запуск SDK/CLI. Номера моделей и версии пакетов не закрепляются этим исследованием: реализация фиксирует совместимый bundle и проверяет canary.

## CR01

[Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview). Прочитаны сравнение Agent SDK/CLI/Client SDK/Managed Agents, возможности, условия авторизации и branding. Agent SDK предоставляет готовый цикл Claude Code; прямой Client SDK не подменяет его. Следствие для Dennett: SDK-host оправдан, когда обеспечивает необходимые callbacks. CLI остаётся официальным способом запуска процесса. SDK-backed продукт и официальный бинарник обозначаются различно; доступ к подписке не выводится из технической доступности метода. Это документация производителя, не независимый benchmark.

## CR02

[Streaming Input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode). Прочитаны рекомендуемый streaming input и ограничения single-message режима. Следствие: проверять многотуровый ввод, прерывания, изображения и callbacks выбранной поверхности, не только наличие output stream. Наша привязка пользовательского ответа к конкретному запросу — проектное решение, проверяемое C06, а не гарантия транспорта по умолчанию.

## CR03

[Run Claude Code programmatically](https://code.claude.com/docs/en/headless). Проверены machine output, bare mode, trust/config loading, lifecycle фоновых работ и завершение процесса. Следствие: CLI не парсится как терминальная картинка; отключение автозагрузки и иной вход в bare mode должны быть осознанными. Продолжение обязательства после остановки CLI организует Dennett, не вечный процесс shell. Конкретные таймауты документации не становятся неизменными системными требованиями.

## CR04

[Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions). Проверены явный resume ID, continue последней сессии, fork, локальное сохранение и отсутствие snapshot файлов при сохранении разговора. Указано удаление экспериментального TypeScript V2 session API. Следствие: использовать поддержанную `query()`-поверхность и явную привязку ID, отдельно обеспечивать файлы/состояние и isolation. Не обещать перенос скрытого состояния между провайдерами.

## CR05

[Modifying system prompts](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts). Прочитаны minimal default, `claude_code` preset/append, custom prompt и загрузка CLAUDE.md. Следствие: coding-профиль и не-кодирующий оркестратор выбирают подходящие инструкции явно; настройки источников не выводятся из одного названия preset. Наш выбор профилей — конфигурация обычных агентов, не новые классы. Не переносить советы о coding-профиле на всякую задачу.

## CR06

[Use Claude Code features in the SDK](https://code.claude.com/docs/en/agent-sdk/claude-code-features). Проверены `settingSources`, его неполное влияние на global config/managed policy/auto-memory/connectors, filesystem skills/hooks и отличие subagents от CLI agent teams. Следствие: тестировать эффективный контекст и изолировать профиль; не считать пустой список источников полноценной песочницей. Не требуется отключать все полезные настройки навсегда: разрешённые возможности подключаются явно.

## CR07

[Connect to external tools with MCP](https://code.claude.com/docs/en/agent-sdk/mcp). Проверены программное подключение серверов и доступные способы интеграции инструментов. Следствие: memoryd остаётся самостоятельным сервисом, SDK custom tool/MCP — только вход к его прикладной операции. Не встраивать всю память в host и не выдавать MCP-серверу authority только из-за протокола. Совместимость конкретного сервера проверяется отдельно.

## CR08

[Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions). Проверены порядок решений, `allowedTools`, callback `canUseTool` и пропуск callback для ранее разрешённых вызовов. Следствие: обязательную предисполнительную границу нельзя размещать только в callback запроса пользователя; правильность полномочий проверяется и через альтернативный инструмент. Это не обоснование отдельного LLM-контролёра.

## CR09

[Hooks](https://code.claude.com/docs/en/agent-sdk/hooks). Прочитаны interception, `PreToolUse`, разные события/SDK и независимое выполнение matching hooks. Следствие: использовать hooks для нужной интеграции политики/наблюдений, не для повторной реализации агентного цикла. Hook post-event не считается предварительной авторизацией; настоящий sandbox остаётся отдельной границей.

## CR10

[Handle approvals and user input](https://code.claude.com/docs/en/agent-sdk/user-input). Проверены approvals, `AskUserQuestion`, возврат ответа и указанное ограничение этого инструмента у SDK subagents. Следствие: вопрос и разрешение — разные ожидающие операции; недоступное уточнение помощник возвращает родителю. Тестировать поздний/отсутствующий ответ и Stop, не автоматически разрешать действие.

## CR11

[Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents). Проверены prompt поручения, исходный контекст, отличия fork и native возможности. Следствие: пользоваться нативным делегированием без собственного графа; не выдумывать наследование всего контекста и прав. Число помощников и их специализация не фиксируются этим документом.

## CR12

[File checkpointing](https://code.claude.com/docs/en/agent-sdk/file-checkpointing). Прочитаны область файлового возврата и ограничения. Следствие: native rewind не заменяет транзакции, резерв Memory или учёт внешнего эффекта; наши тесты проверяют фактическое состояние. Не обещать возврат всего приложения по одному Claude checkpoint.

## CR13

[Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance). Прочитаны условия размещения неизменённого бинарника, собственный вход пользователя, запрет посредничества в credentials/usage и правила названия. Следствие: разделить hosted/native binary и SDK-продукт; не собирать подписочные токены и не подменять identity клиента. Это фиксация опубликованных условий, не юридическая экспертиза любой будущей формы распространения.

## CR14

[Use the Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan). Проверено действующее уведомление от 15 июня: прежнее объявление изменения тарификации приостановлено; ниже страницы сохранён не вступивший в действие текст. Следствие: не обещать старую схему кредита или бессрочную подписочную тарификацию. Фактический billing не отменяет отдельные условия распространения из CR01/CR13. Перед выпуском перепроверить всё вместе, без автоматической платной замены маршрута.

## Итог и границы проверки

В текущем снимке PR29 ранний план разрешал выбор первого runtime по доступности, а D3 называл Claude последующим подключением; том82 сначала подробно описывал Codex. Новое явное решение владельца заменяет только этот порядок и необходимые детали интеграции. Codex-проект сохранён, но вынесен за D0–D9. Полнота Memory Fabric, текстовые связи, самостоятельный memoryd, PostgreSQL и гибридные интерфейсы не пересматривались.

Проверены официальные страницы и согласованность изменённых документов. SDK/CLI, вход, реальные модели, hooks, загрузка настроек и новая программа в этом проходе не запускались. Эксперименты C01–C12 обязательны в новой реализации, не отмечены выполненными. Архивы и прежние исследования сохраняют исторические формулировки, но не задают текущий порядок подключения.
